# Desktop workflow verification

The desktop checks run native MATLAB and Simulink R2026a on Linux. They drive the actual launcher, editor and value-selection callbacks. File-dialog test substitutes supply the destination paths. Models are generated by the same functions called by the buttons, then simulated to check the resulting waveforms.

The synthetic example starts with a constant input of 3. A bias of 1 followed by a gain of 2 produces 8. The test adds and removes a further stage, selects two bias values and two gain values through the value dialog, saves the settings, reopens the model, and loads the saved configuration through the launcher.

| Check | Result |
|---|---|
| One enabled fault per model | Four compiled models with outputs 2, 4, 6 and 12 |
| Campaign combinations | Eight compiled models with outputs 2, 4, 4, 8, 2, 4, 8 and 16 |
| Campaign simulations | All eight cases and the all-off baseline completed with the expected output at every recorded time |
| Compilation failure between valid cases | Two valid models retained and the middle failure recorded |
| Cancellation | The completed model retained |
| Signal routing | Stem and branch faults preserved their effects after adding, removing, saving and reopening stages |

The aircraft check uses the original FIM AECS model and its 45-location configuration. It adds a gain stage after the first bias, sets its candidate values in the desktop dialog, then generates three individual-fault models and four campaign models. Each generated model is reopened and simulated with the same built-in pilot command and random seed. The recorded control-law output is checked against the expected bias and gain transformation during the configured time window. [Synthetic results](workflow.csv) · [Aircraft results](aecs.csv) · [Original model setup](../fim_paper/README.md)

From the source checkout, add `benchmarks` to the MATLAB path and call `verify_desktop_workflow(outputFolder)` or `verify_fault_chains(outputFolder)` with a fresh folder. The aircraft check is `verify_desktop_aecs(authorsCheckout,outputFolder)`. Installed copies also include these checks.

The existing editor checks on all 12 ARCH-COMP models, their 48 campaign cases, and the 53 fault-semantics comparisons were rerun. Their numerical result files matched the previous recorded results.
